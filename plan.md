# Hey Bro — Day 10 implementation plan

Keep the accepted zinc/emerald mobile-first brand and current Next.js15 App Router/TypeScript/Tailwind stack. The catalogue will generate actual city/suburb/category URL parameters during the static build. It will not create invented suburb inventory or pretend that an empty preview is a thousand-page production directory.

A typed snapshot pipeline reads approved category/location data from Supabase when public client configuration is available. Without that configuration it imports the existing explicitly fictional feed. Database reads are bounded and paginated, and a failed configured import must not silently masquerade as successful live data. Generated snapshots contain public listing fields only. The importer never queries escort-service categories. The requested escorts example is a neutral, noindex unavailable page with no listing/contact/directions facilitation.

The route catalogue generates populated location/category combinations, plus the requested empty/unavailable preview examples. Canonical slugs reject unrecognized paths with404s. Quick suburb links target generated pages; any category switch is labelled. Thousands of pages require thousands of genuine approved catalogue combinations, not automatic publication of thin empty permutations.

A shared application shell preserves the age-gated header/feed/footer. Existing home and venue routes move into an internal route group without changing their public paths. The root layout keeps document metadata/styles. Local pages use the same shell with a safe public introduction: H1, locality/category description, listing titles and suburb links. Before acceptance this public introduction is present in HTML but inert behind the gate; interactive listings/photos/contact and map controls are not mounted. After acceptance it appears inside the normal main layout. This is identical visitor/crawler content, not a User-Agent bypass.

## Day 19 — Abuse controls, security headers and crawlers

Keep the existing Next.js TypeScript configuration and App Router robots metadata route; they serve the requested config and `/robots.txt` endpoints without duplicate incompatible files. Add a server-only `lib/rateLimit.ts` helper that enforces route-specific request budgets before parsing bodies or database work: tracking 120/minute, review reads 60/minute and review POST attempts 5/10 minutes. Exceeded budgets return 429, Retry-After and no-store. Apply a small bounded local counter for the unconfigured preview, and an atomic private Supabase RPC shared across instances when private DB credentials exist; configured backend failure fails closed rather than silently downgrading. Preserve existing SQL review quotas, payload validation, moderation and idempotent submissions.

Rate keys never come from nickname, venue ID or request body. Default unidentified traffic uses a conservative shared bucket because this platform does not document a trustworthy forwarded-IP header. Only an explicitly configured, ingress-overwritten single IP header may distinguish clients; arbitrary forwarded-for/client-IP headers are not trusted by default. Use domain-separated HMAC keys, retain no raw IP/location and bound counter state/expiry. A stable server secret can be explicit or an existing private injected server secret; transient fallback is only for the local preview. Distributed counters require the new SQL migration and private server credentials.

Add application-wide nosniff, referrer, permissions, HSTS and other low-risk headers, plus compatible CSP restrictions for base/object sources. Do not send X-Frame-Options DENY/SAMEORIGIN, restrict frame-ancestors to self or enable COEP that would break Preview, OAuth, external OSM tiles, app images or PWA. A strict script nonce rollout is not introduced into existing SSG pages/platform-injected scripts. Keep all admin/API private no-store/noindex headers intact.

Robots rules explicitly allow Googlebot/Googlebot-Image on the configured publication origin and disallow selected nonessential scraper/AI crawl user-agents, while private APIs/admin and Preview remain disallowed and public OG remains allowed. These are advisory crawl directives, not authentication or a guarantee against spoofed bots. Real enforcement is server request limiting; volumetric and multi-network abuse still needs trusted ingress/WAF policy.

## 커뮤니티 토론 진입점 노출과 Reddit 로고
